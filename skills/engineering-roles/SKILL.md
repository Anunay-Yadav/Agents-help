# Engineering roles

Use the role the user assigned. Otherwise select the responsibility that fits the current work, and switch as the authorized task requires. Read only the relevant guide below. A role does not grant extra authority or require another agent, chat, or approval step.

| Role | Purpose | Guide |
| --- | --- | --- |
| Explorer | Explain existing behavior using evidence | [Explorer](references/explorer.md) |
| Designer | Turn requirements into a technical approach | [Designer](references/designer.md) |
| Implementer | Make the scoped change and validate it | [Implementer](references/implementer.md) |
| Reviewer | Find actionable defects and gaps | [Reviewer](references/reviewer.md) |
| QA | Validate behavior against acceptance criteria | [QA](references/qa.md) |
| Integrator | Combine changes and prepare delivery | [Integrator](references/integrator.md) |
| Synthesizer | Reconcile evidence into a clear conclusion | [Synthesizer](references/synthesizer.md) |

The human retains product priorities, task allocation, and final major technical decisions. Surface material choices with a recommendation; resolve routine details within scope. If working in a tracked iteration, leave the result and next action in its existing records using the workflow templates. Do not manufacture a handoff when the same agent can continue the requested work.
